How scoring works

Each puzzle gives you a situation, a legend of relevant skills, and one question: what is the chance? You answer with a slider from 0 to 100%, press Submit, and immediately see the real number, how far off you were and a worked solution.

  • Hit / miss: a guess within ±5 percentage points of the true chance counts as a hit (a puzzle may set its own wider tolerance — the reveal always tells you which one applies). This tolerance exists because a slider cannot express values such as 74.07% — without it, the puzzle would be unfair.
  • Error: the absolute distance between your guess and the true answer, in percentage points (pp).
  • Accuracy: hits ÷ puzzles, shown with a 90% Wilson confidence interval.
  • 90% interval of your error: a t-interval on your average miss distance. It answers "how precisely did this run measure my skill?" — repeat the run and about 9 of 10 such intervals would contain your true average error.
  • Leaderboard: sorted by accuracy, then by smaller mean error. You may save your result anonymously or with a nickname.
The formulas, because you are among friends

mean error = (1/n) · Σ |guessᵢ − answerᵢ|
90% CI = mean ± t₀.₉₅,ₙ₋₁ · s / √n   (s = sample standard deviation)
accuracy CI (Wilson) = (p + z²/2n ± z·√(p(1−p)/n + z²/4n²)) / (1 + z²/n), with z = 1.645

With a handful of puzzles these intervals are wide — that is the honest answer, not a bug. Add more puzzles to the deck and the interval narrows.

Checking the odds — Dave's Action Calculator

Every puzzle page has a 🧮 Odds calculator box: type the turn as a calculation string and press Open ↗ to get the exact success chance from Dave's Advanced Action Calculator (the string travels in the link as ?c=…, so anything you build is shareable and bookmarkable). The calculator answers one question — what is the chance this whole line works? — and lists it for 0, 1, 2 … team rerolls; read the row that matches the rerolls the puzzle gives you. Skills such as Dodge, Sure Feet, Catch, Pass or Pro are spent automatically where they help.

The line

Actions of one player, in order, separated by commas. A letter plus the target number; a bare number is a generic rerollable roll, and n/m is a fixed chance that cannot be rerolled.

Blocks

<dice>D<good faces> — dice = 1, 2 or 3 (negative -2/-3 when the defender chooses the die), good faces = how many of the block die's faces count as success, best first (defender down, then the pushes, then both down, then the skull): 1D2 = one die for a knockdown, 2D2 = two dice for a knockdown, 2D3 = two dice for push-or-better, 3D1 = three dice for POW only, 1D5 = one die for anything but the skull (a blocker's view of both down). !n marks the n faces below the good ones as "safe but not a success" — that is how frenzy follow-ups are written: 2D2!2{1D2} = a 2-dice block for the knockdown whose pushes trigger the branch in {…}. Modifiers: ^ Brawler, * Pro, % Hatred, ' do not reroll the safe-but-not-success faces.

Skills and more players

Skills go in front of the actions, before a colon: D,SF:D3 = dodge 3+ with Dodge and Sure Feet, L4:2D2 = a loner (4+) player blocking, MB2:2D3,K8 = mighty blow (+2) into the armour roll. Common codes: D Dodge, BT2 Break Tackle 2+, SH Sure Hands, SF Sure Feet, PA Pass, C Catch, DC Diving Catch, B Brawler, CL Claw, MB1 Mighty Blow, P Pro, L4 Loner 4+, DP1 Dirty Player, SG Sneaky Git. A ; switches to the next player: P3;C:C3 = the thrower passes 3+, then the catcher (Catch) catches 3+. Star players are addressed by short name, e.g. Morg:2D2,H5;G4.

Branches

  • {…} — what happens if the action before it did not fail critically (frenzy follow-up blocks).
  • […] — a branch that ends the calculation, e.g. scoring the touchdown on the way.
  • (a)(b) — alternative lines, e.g. two routes; the calculator picks the best plan.
  • | — the dauntless split: L2,2D2|1D2 = dauntless 2+, then a 2-dice block if it is made or a 1-die block if it is missed.
  • ~S2 — suffix that switches the whole calculation to Season 2 rules.

Worked samples

  • D:D2,D2,D2 — sprint through three tackle zones: three 2+ dodges with the Dodge skill. Row 0 = no team reroll left, row 1 = one reroll in the bank.
  • 3D3,K6,J7 — a 3-dice block that puts the victim down (87.5%), armour 6+ (72%), injury 7+ for the KO or casualty (58%): about 37% end to end.
  • SH,PA:P3;C,DC:C3 — a thrower with Sure Hands and Pass throws a 3+, a teammate with Catch and Diving Catch takes it on 3+.
  • 2D2!2{1D2} — frenzy: the pushes of the first block trigger a 1-die follow-up.
  • D,SF,L4:D4,D4 — a loner (4+) with Dodge and Sure Feet dodging twice at 4+.
  • P4-2;C2 — a long pass (4+ with a −2 modifier) caught on 2+ by the next player.

Players see it together with the solution after submitting, and it is dropped into the puzzle page's calculator box so it can be inspected and edited. Hosting on GitHub Pages (5 minutes)

  1. Create a repository, e.g. blood-bowl-puzzles, and push the contents of this folder to the main branch.
  2. In the repository: Settings → Pages → Source: Deploy from a branch → Branch: main, folder: / (root) → Save.
  3. Wait a minute. The site appears at https://<your-login>.github.io/blood-bowl-puzzles/.

Naming the repository <your-login>.github.io publishes it at the bare domain instead. Everything here is plain static files: no build step, no Node, no bundler.

Heads-up: a module-based site like this one needs http(s). Opening index.html directly from file:// will not load puzzles.json — use GitHub Pages, or a local server such as python3 -m http.server 8000.

Turning on the shared leaderboard (Firebase, free)

  1. Go to console.firebase.google.com → Add project (Google Analytics can be skipped).
  2. In the project: Build → Firestore Database → Create database. Pick a region and start in production mode.
  3. Project settings → Your apps → Web (</>) → register an app. Copy the firebaseConfig object.
  4. In this repository, copy js/config.example.js to js/config.js and paste your values in. Commit and push.
  5. Paste the rules from firestore.rules into Firestore → Rules and publish. They allow reading the leaderboard, adding a result of a plausible shape, and nothing else.
Your firebaseConfig keys are not secret — they are meant to be public in web apps; the rules above are what actually protects the data. Until config.js contains real values, the site quietly keeps the leaderboard in localStorage for the player's own browser and says so in the header.

Adding puzzles

  1. Open the puzzle editor, fill in the form, watch the JSON and the preview, then Add to export.
  2. Press Download puzzles.json.
  3. Put your pitch images into the images/ folder and reference them as images/your-file.png.
  4. Commit the new puzzles.json and images. The site picks them up on the next page load — no rebuild.

The deck order in the editor is the order the player sees. Deeper puzzles usually work better late in a run.
