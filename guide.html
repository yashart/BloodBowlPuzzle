How it works

Each puzzle gives you a situation and a legend of the relevant skills. You answer in two independent ways:

  • How to play (always): press the action buttons in the order you would do them — block 1d, block 2d, block uphill, dodge, gfi, pass, catch — and your solution builds up under the panel, e.g. block 2d, dodge. clear starts it over. Submit and you get the correct sequence and the full worked solution.
  • Odds prediction (optional): if the puzzle carries a correct answer, a 0–100% slider appears as well. Leave it alone with the Skip the odds checkbox and you will simply be shown the real number — nothing is scored against you.

There is no win/lose condition and no accuracy score. After the reveal you get the right odds and the solution text; the end of the run shows a recap with the correct odds and solution for every puzzle.

The one formula we still use

error = |your odds − correct odds|   (percentage points)
mean error = (1/n) · Σ errorᵢ   (over the puzzles where you predicted odds)
90% CI of the mean = mean ± t₀.₉₅,ₙ₋₁ · s / √n

The interval is just context for the recap: with a handful of puzzles it is very wide. Skipping the odds on a puzzle simply removes it from the average.

Hosting on GitHub Pages (5 minutes)

  1. Create a repository, e.g. blood-bowl-puzzles, and push the contents of this folder to the main branch.
  2. In the repository: Settings → Pages → Source: Deploy from a branch → Branch: main, folder: / (root) → Save.
  3. Wait a minute. The site appears at https://<your-login>.github.io/blood-bowl-puzzles/.

Naming the repository <your-login>.github.io publishes it at the bare domain instead. Everything here is plain static files: no build step, no Node, no bundler.

Heads-up: a module-based site like this one needs http(s). Opening index.html directly from file:// will not load puzzles.json — use GitHub Pages, or a local server such as python3 -m http.server 8000.

Turning on the shared leaderboard (Firebase, free)

  1. Go to console.firebase.google.com → Add project (Google Analytics can be skipped).
  2. In the project: Build → Firestore Database → Create database. Pick a region and start in production mode.
  3. Project settings → Your apps → Web (</>) → register an app. Copy the firebaseConfig object.
  4. In this repository, copy js/config.example.js to js/config.js and paste your values in. Commit and push.
  5. Paste the rules from firestore.rules into Firestore → Rules and publish. They allow reading the leaderboard, adding a result of a plausible shape, and nothing else.
Your firebaseConfig keys are not secret — they are meant to be public in web apps; the rules above are what actually protects the data. Until config.js contains real values, the site quietly keeps the leaderboard in localStorage for the player's own browser and says so in the header.

Adding a category or a set

The landing page is driven by sets.json. A category has a title, a description and a list of sets; every set points at its own puzzles.json file. The landing page shows one row per set with just the pack name and how many puzzles it holds; the row plays the set and the small json link opens the deck file.

{
  "id": "my-cup",
  "title": "My Tournament",
  "description": "Puzzles from last weekend.",
  "sets": [
    {
      "id": "round-1",
      "title": "Round 1 — Bash",
      "file": "puzzles/round-1.json",
      "count": 2,
      "description": "Two puzzles, no rerolls."
    }
  ]
}

count is optional and only printed as “N puzzles” on the row; the set always plays whatever the JSON file actually contains. description is used as the row's tooltip.

A set is also playable directly, without the landing page: play.html?set=puzzles/round-1.json. Links are relative, so this works just as well on GitHub Pages.

Adding puzzles

  1. Open the puzzle editor, fill in the form, watch the JSON and the preview, then Add to export.
  2. Press Download puzzles.json.
  3. For the pitch image you can either put a file into the images/ folder and reference it as images/your-file.png, or paste a link to an image on the web (https://…/pitch.png). Links must point at the image itself, not at a gallery page.
  4. Commit the new puzzles.json and images. The site picks them up on the next page load — no rebuild.

The deck order in the editor is the order the player sees. Deeper puzzles usually work better late in a run.

What each file does

FileRole
index.htmlThe landing page: puzzle sets grouped by category, each linking to its own puzzles.json.
play.htmlThe quiz: puzzle screen, action panel, optional odds slider, reveal, recap. Reads ?set=path/to/puzzles.json.
sets.jsonThe catalogue the landing page renders: categories and the sets (deck files) inside each.
puzzles/Themed decks, e.g. puzzles/scoring.json — just more puzzles.json files.
editor.htmlThe puzzle authoring form with live JSON and preview.
puzzles.jsonThe default deck, and the one play.html falls back to without ?set=.
js/app.jsQuiz flow: action buttons, optional odds, reveal and recap.
js/engine.jsMarkdown subset, statistics (t-interval, Wilson), puzzle loading and validation.
js/leaderboard.jsFirebase or localStorage leaderboard behind one API.
js/editor.jsEditor logic and export.
js/config.jsYour Firebase credentials (created locally, never committed in the repo template).
images/Pitch artwork. The demo files are SVGs generated from coordinates, replace them freely.
site-src/Optional Python helpers used to generate the demo content and to validate the deck.
